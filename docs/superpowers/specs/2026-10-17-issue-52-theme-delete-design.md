## Recommended design

Use DownloadService's existing admission lock as the short mutation boundary for publication, delete and worker reconciliation. Add a canonical-folder revision map owned by that same lock. At admission, capture the resolved folder and revision alongside the existing job generation; deletion increments the revision, invalidating all pre-delete attempts targeting that folder, including jobs waiting for its landing gate. A new, explicitly admitted post-delete attempt may download normally.

Expose coordinated `DeleteTheme(string id, string mediaType)` and `ReconcileTheme(string id, string mediaType)` operations on DownloadService. Controllers retain containment validation; the coordinated delete rechecks the current folder and roots before changing files. Under the admission lock, advance the folder revision BEFORE any filesystem mutation; then reserve the SQLite writer, delete final theme files and reset stored status/recheck state. The revision remains advanced even if deletion is partial or its database transaction fails, so an error cannot reauthorize older work. Never hold either lock over provider/network I/O or Plex refresh. All code uses the same order: admission lock → SQLite write reservation. Provider work retains its existing folder gate, followed by the admission lock only for final publication. No path may acquire that folder gate while holding the admission lock.

Ordinary publication must check both attempt generation and folder revision before any promotion, history insert or recheck clearing. An invalidated attempt finishes with a specific cancellation error, cleans its own staging file while still owning the landing gate, and cannot erase a later attempt's staging. Reconciliation repeats the disk check inside the same short mutation/SQLite boundary as its status update; preserve the cheap stored-pending prefilter.

For movie/show rows sharing a folder, invalidate both types' pre-delete jobs and reset both stored rows because the physical theme belongs to the folder. Preserve ignored flags and Plex-owned theme information. Match folders with the same canonicalization as the landing gate; include trailing-separator aliases in tests.

## Semantics and limitations

`deleted` means at least one final theme was present and removed by the serialized operation. With no final file it remains false, but deletion still invalidates an older pending attempt and reconciles absent-file status. Failures deleting a real file must surface; do not report success. External programs can still change files outside Themearr's locks; the guarantee covers in-process writers, not a filesystem transaction across Plex or manual shell changes. SQLite rollback cannot restore a deleted file; if a DB write fails after deletion, report failure and arrange status reconciliation rather than claim an atomic filesystem/DB rollback. Keep a coalesced in-memory dirty-folder set; both workers drain it before their stored-status prefilter, removing entries only after successful disk/status reconciliation and retaining failed entries with a sanitized diagnostic. Restart loses that set; do one startup reconciliation of unfinished mutation records only if durable recovery is subsequently required, rather than claiming crash durability for this in-process fix.

Keep synchronous controller signatures and best-effort Plex refresh outside the critical section ([src/Themearr.API/Controllers/MoviesController.cs @ e81b25f, lines 86–93](https://github.com/Themearr/themearr/blob/e81b25f4c487dc5406b93cab9bf3736d2da4aad9/src/Themearr.API/Controllers/MoviesController.cs#L86-L93), [src/Themearr.API/Controllers/ShowsController.cs @ e81b25f, lines 231–238](https://github.com/Themearr/themearr/blob/e81b25f4c487dc5406b93cab9bf3736d2da4aad9/src/Themearr.API/Controllers/ShowsController.cs#L231-L238)). Automatic downloading may legitimately create a newly admitted download after deletion; the guarantee is that pre-delete work cannot resurrect it.

## Acceptance and propagation

Force all three issue interleavings with held providers/commit barriers, for movies and shows, and cross-type shared folders. Assert disk files, raw stored status, history/provenance, recheck flags and terminal job error, not just disk-derived list status. Retain all existing replacement-ownership and folder-gate tests unchanged. No new user-facing capability or schema is proposed. Dashboard/queue derive corrected state; history records only committed downloads; settings and System need no new controls. Require security-invariant and concurrency reviewers.
