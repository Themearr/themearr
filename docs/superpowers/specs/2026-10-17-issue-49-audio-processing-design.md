## Proposed settings and processing

Add a settings object `audioProcessing` with `enabled:false`, nullable `trimSeconds`, `normalize:false`, `bitrateKbps:192`. A Plex-oriented preset sets trimSeconds to 30 only when the user chooses it. Enabled processing always encodes MP3; trim and normalization remain independently optional. Do not infer media-player behavior from the library source: a Plex-sourced media folder can also be used by other players. The default leaves all current bytes and durations untouched.

Recommended bounds: trimSeconds null or integer 5–900; bitrateKbps from 128/192/256/320. Normalization uses two-pass loudnorm with proposed targets -16 LUFS, -1.5 dBTP and LRA 11, an explicit 44.1 kHz stereo output, and finite/silence-result checks. Trim to the opening segment before measuring normalization, so both passes analyze the same segment. These are product defaults, not current code facts. [FFmpeg documents loudnorm and its two-pass measurements](https://ffmpeg.org/ffmpeg-filters.html#loudnorm).

Introduce IThemeAudioProcessor after provider/direct HTTP download and before final promotion; do not add another audio provider or modify matching. Invoke ffmpeg/ffprobe only on local staged files, using ProcessStartInfo.ArgumentList with no shell and a fixed protocol allowlist excluding network access. Drain stdout/stderr, bound their retained content, kill the process tree on cancellation/timeout, cap input/output sizes and concurrency, and validate a nonempty decodable output. Retain a good existing theme on every processing failure. Processing explicitly requested but unavailable must fail visibly, never silently store an unprocessed track.

Use unique staging names; only a verified MP3 becomes theme.mp3 through the existing commit coordination. Processing must share #52's folder-revision invalidation and must not hold SQLite over encoding. Time budget recommendation: 120 s per file, one encoder at a time; retain a bounded overall download deadline. All failures preserve the original and remove temporary output. Do not change full-length defaults for Kodi, Emby or Jellyfin.

## Repair contract

Split preview from apply. Authenticated POST `/api/audio-repair/preview` accepts media scope and processing options and returns a preview ID plus selected item/file fingerprints, before/estimated-after bytes and exclusions. Preview scans local final themes only, performs no provider calls and writes no media. Exclude ignored items by default; explicitly selected manual/kept items may be repaired, preserving their selection provenance and recheck verdict. Collapse movie/show aliases to one canonical physical file.

Authenticated POST `/api/audio-repair/apply` accepts only a server-issued preview ID and selected preview item IDs. A bounded single repair job exposes GET `/api/audio-repair/status` and POST `/api/audio-repair/cancel`. Reject expired or unknown previews with HTTP 409; retain at most one preview for 15 minutes, and invalidate it when processing options change. Return per-file outcomes and actual source-file savings. Revalidate roots, file hash, revision and preview options immediately before commit; a download/delete since preview makes that file stale and skipped, never overwritten.

Make a sibling backup outside the theme.* namespace before replacing each repair input. Require enough free space for input+output+backup. Restore from it on a detected commit failure within the same live mutation boundary, before any newer writer can intervene; retain the backup until the operator explicitly removes it outside this first version. Report retained-backup bytes separately so 'source savings' is not confused with actual reclaimed disk space. Record fingerprint/options/success in a separate repair ledger to avoid repeated lossy encoding; never forge a new theme selection/history event.

Before publication, persist input hash, prepared output hash, options and backup/staging paths. After restart, recovery is read-only for media: if the current final file exactly matches the prepared output hash, finalize only the ledger as succeeded; otherwise mark interrupted and require a fresh preview. Never automatically restore a backup, resume encoding or overwrite a differing current file. A source file changed after the crash may belong to a newer download. This is the recommended conservative recovery policy, settled after independent builder review.

## Plex storage caveat and delivery

Repair changes the media-folder copy. Plex's imported metadata copy is separate; report no Plex metadata savings and never edit Plex bundle directories. Request best-effort per-item metadata refresh after each successful change, and provide instructions for Plex Clean Bundles. [Plex distinguishes refresh from scan](https://support.plex.tv/articles/200289306-scanning-vs-refreshing-a-library/) and [documents bundle cleanup](https://support.plex.tv/articles/226836308-help/). Whether a particular Plex version reclaims superseded theme copies needs a controlled before/after acceptance test; the issue's observation is not a reclamation guarantee.

Ship a README storage-growth note independently. Processing requires packaged ffmpeg/ffprobe for Docker amd64/arm64; native installations get explicit dependency instructions/detection. The Proxmox installer is in a separate [Themearr/ProxmoxVE repository](https://github.com/Themearr/ProxmoxVE/blob/main/ct/themearr.sh), referenced by README; dependency packaging needs a coordinated follow-up there. Do not silently require ffmpeg for the unprocessed path.

Settings exposes the option/preset and warnings about shared players. System reports encoder availability plus repair progress/cancel and before/after/backup totals. Queue and both media pages report processing failures through their existing download feedback. History preserves selection provenance and links to a separate repair report. Dashboard download coverage remains file-derived; no new 'download' count for a repair. Both security-invariant and concurrency reviews are required. Split into documentation, new-download processing, and repair releases; repair depends on #52 and stable attempt tracking from #55.
