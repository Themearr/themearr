## Additive protocol

Add `DownloadStartResult(bool Started, Guid? AttemptId)` and `StartAttempt(...)` with the current Start parameters. Keep `bool Start(...)` as a compatibility wrapper calling StartAttempt once. Reservation must return the exact newly reserved generation while still under the admission lock; never call bool Start and then independently read status to discover its generation.

All six movie/show manual, URL and auto-download start routes keep their current status codes/fields and add `attemptId` on successful acceptance. Conflict remains HTTP 409 and does not masquerade as a new successful attempt.

Status keeps `inProgress`, `finished`, `error`, `logs` and adds nullable `attemptId`, `known` and `state`, where state is `unknown | pending | running | succeeded | failed | superseded`. Reserve as pending before scheduling; transition to running only when the current attempt obtains its folder landing gate. No job for a key is `known:false, state:unknown, attemptId:null` with legacy false booleans. Unknown does not assert whether a POST is still in transit or a job existed before restart; the server cannot know that.

Accept an optional requested attempt in status queries. A matching attempt returns its snapshot. A different current generation returns `state:superseded`, echoes the requested attempt id, includes `currentAttemptId` for diagnosis, and emits no other attempt's logs or terminal result. Keep only the current attempt per key; attempt history is not a new durable table. A server restart returns unknown for a previously known attempt.

## Client adoption and compatibility

Define typed start/status DTOs in the web types module. Extend the adapter status method with an optional third attempt-id parameter, preserving its existing `(id, init?)` call shape. Adapter start results may omit attemptId for compatibility with an older server and existing mocks. Keep the shows adapter's current composed auto-download flow in this change ([src/Themearr.Web/src/lib/media/adapter.ts @ e81b25f, lines 67–71](https://github.com/Themearr/themearr/blob/e81b25f4c487dc5406b93cab9bf3736d2da4aad9/src/Themearr.Web/src/lib/media/adapter.ts#L67-L71)); pass through the final download result. Its manual provenance discrepancy is a separate follow-up, not a reason to rewrite adapter tests here.

Queue and SearchModal capture returned attemptId, request status for that attempt, and refuse mismatched terminal snapshots. Unknown or superseded after an accepted start is an explicit lost-tracking message; release controls without auto-advancing or automatically spending quota on a retry. Missing new fields use the current legacy path. Keep all existing start-settled, latest-client-attempt, timeout and stale-screen guards.

## Acceptance and propagation

Tests must exercise actual StartAttempt and controller responses, not only DTO constructors. Cover simultaneous starts, retry generation changes, old completion after watchdog admission, colliding movie/show IDs, queued work, unknown before any start, restart-like empty state, and stale polls. Frontend tests cover queue and modal, direct URLs and provider downloads, plus mixed old/new client-server shapes. No database migration. History remains successful-download provenance; dashboard counts are unchanged; System's active-work calculation must still include pending attempts; settings needs no control. Require concurrency review and security review of touched download/controller paths.
